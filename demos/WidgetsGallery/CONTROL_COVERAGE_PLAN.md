# 内置控件分类与示例扩充

## 验收目标
- 以 `SOUI/src/SApp.cpp` 的实际内置注册和类定义为准，不将扩展控件、别名或内部辅助对象重复计数。
- 按分类展示不同的真实控件类型；每个公开可视类型有命名实例、明暗 Fluent 配套资源、准确 XML 和必要的 C++ 初始化用法。
- 重点补全 Button、ListBox / ListView / 多列视图 / TileView / TreeView，虚拟视图必须接真实 adapter。
- 继续保留原有进度、搜索、单选键盘、编辑、列表增删、弹窗及运行时换肤行为。
- 公开覆盖矩阵，区分独立控件、复合子节点、宿主集成接口和平台限制；不能将空占位当作完整演示。

## 实施顺序与边界
1. 清点注册和现有用法，建立机器可检验的控件目录。
2. 在本 Demo 内增补各类控件、adapter、语义皮肤和源码展示；不改框架公共 API、共享系统资源或其他 Demo。
3. 生成资源与目录索引，扩展资源/建树/运行期/GUI 回归，实际构建 Windows Debug。
4. 运行全量无头检查和代表性的真实 GUI 交互，逐次检查浅深截图；记录未覆盖平台和弹层像素限制。

## 验证方式
- 目录测试：注册的公开控件全部进入矩阵，唯一 class/tag/sample，XML 示例与真实实例一致。
- 资源测试：两套 skin/token 对称、SVG 状态条尺寸和引用合法、资源生成可重复。
- C++ 回归：真实建树，检查具体类型、adapter 数量/数据/选择、主题往返及新增控件事件。
- GUI：通过本次 PID 的 HWND 操作导航、虚拟列表/表头/树/数值/日期/容器等；查看实际渲染，不把建树当作像素验收。

## 风险与范围
- 适配器及隐藏/脱离子树的皮肤更新、滚动中新建行、复合控件子节点是主要风险。
- ActiveX、realwnd 等是宿主集成契约而不是新的通用 UI 皮肤；需要诚实标注平台/外部组件前提。
- 本轮不增加运行时依赖，不启动网络导航或第三方 COM 对象；不宣称已验证非 Windows 平台。
